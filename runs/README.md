# runs/

One subdirectory per experiment, named `<nickname>_<YYYY-MM-DD>_<description>`.
Each run directory is self-contained.

## Per-run layout

| File | Role | Committed? |
|------|------|------------|
| `run.yaml` | Declarative intent: which template (from [legoESM-ocean-runners](https://github.com/lesommer/legoESM-ocean-runners)), overrides, machine, status | yes — you author it |
| `config.yaml` | Fully resolved configuration (generated by `bin/run-experiment init`) | yes — generated |
| `experiment.tag` | Provenance record: legoESM commit, runner tag, config hash, execution host/date (generated by init/run) | yes — generated |
| `notes.md` | Free-form human notes on setup, results, observations | yes |
| `*.py` / `*.ipynb` | Per-experiment analysis scripts and notebooks | yes |
| `*.png` | Small analysis figures | yes |
| `*.nc` / `*.npz` / `diagnostics.json` / scheduler logs | Model output and runtime data | **never** — git-ignored |

## Status vocabulary

`run.yaml` carries a `status` field, updated as the experiment progresses:

| Status | Meaning | Expected files |
|---------|---------|----------------|
| `planned` | Declared, not yet initialized | `run.yaml` (optionally `notes.md`) |
| `submitted` | Initialized and/or queued | `run.yaml`, `config.yaml`, `experiment.tag` |
| `running` | Currently executing | `run.yaml`, `config.yaml`, `experiment.tag` |
| `completed` | Finished successfully | + `experiment.tag` with `execution_hostname`/`execution_date`, `notes.md` |
| `failed` | Finished with errors | + `notes.md` with error details |

## Workflow

Declare locally (`run.yaml`, status `planned`), push; on the target machine `git pull`,
`bin/run-experiment init runs/<name>/`, run, update status, commit provenance, push;
pull locally and analyze. See `AGENTS.md` for the full lifecycle.

Experiment templates live in [legoESM-ocean-runners](https://github.com/lesommer/legoESM-ocean-runners) —
this repo only references templates by name and adds per-run overrides.
